#+TITLE: Performance audit (Cachegrind / hot paths)
#+OPTIONS: toc:2 num:t author:nil

This note records concrete engine hot-path issues found in =rsxcore=, how they
were measured on **rg.terra** with Cachegrind, and what shipped optimisations
change. Evidence files live under the implementer scratch directory for the
perf goal run (and are summarised in-repo after deltas).

* Issue 1 — =find_median= full =sort_unstable= (depth exact mode)

** Mechanism

=commands/depth.rs= (exact mode) accumulates per-individual depth vectors then
calls =stats::find_median=. The previous implementation fully sorted each
vector (=O(n log n)= comparisons and moves) only to read the middle order
statistics. Selection at =k_upper = n/2= partitions the vector; the lower
middle value for even lengths is the maximum of the left partition.

** Evidence

- Code: =rsxcore/src/stats.rs= (=find_median=), call site =commands/depth.rs=.
- Cachegrind: depth leg of =scripts/perf/run_cachegrind_workload.sh= on
  =benchmarks/data/medium= (before/after Ir totals under scratch
  =cachegrind-baseline.txt= / =cachegrind-after.txt=).
- Accuracy: =test_find_median_*= and
  =test_find_median_matches_sorted_definition= (selection matches the average
  of sorted[=(n-1)/2=] and sorted[=n/2=]).

** Fix

=slice::select_nth_unstable(k_upper)= with =k_upper = len/2=, followed by a
maximum scan of the left partition for even lengths. Averaging the lower and
upper middle values yields the mathematical median without a full sort. The
redundant full =sort_unstable= in =depth= exact mode is also absent; min/max
use linear scans. Lean: =proofs/lean/MedianSelect= (index theorems). SymPy/Python
PEP 723: =scripts/sympy/median_select_proof.py=.

* Issue 2 — =fisher_exact= per-marker heap =Vec= for tail log-probs

** Mechanism

=stats::fisher_exact= (used by =signif --test fisher= and triage-adjacent
paths) formerly pushed every extreme-table log-probability into a =Vec<f64>=
then ran log-sum-exp. For every marker this allocates/resizes a small vector
and streams it twice (max + sum), adding instruction traffic and allocator
pressure on the Fisher signif path.

** Evidence

- Code: =rsxcore/src/stats.rs= (=fisher_exact=).
- Cachegrind: signif Fisher leg of the same workload script (Ir drop attributed
  primarily to fewer alloc/copy paths in the hot loop).
- Accuracy: existing =test_fisher_exact_*= (same tail definition, online
  logsumexp).

** Fix

Online log-sum-exp over the density tail (no intermediate =Vec=). Pure
accumulation refactor of the same sum — not a new statistical model.

* Issue 3 (supporting) — =fast_parse_u16= general loop for short depths

** Mechanism

Depth fields in RAD TSVs are almost always 1–3 ASCII digits. The previous
always-on saturating loop paid overflow branches for every field. An unrolled
path for =len ∈ {1,2,3,4}= reduces instruction count on the parse-heavy
=for_each_skip_seq= / full paths (=markers_table.rs=).

** Evidence / fix

- Code: =rsxcore/src/io/table_io.rs= (=fast_parse_u16=).
- Accuracy: =test_fast_parse_u16= (including saturation cases).
- Cachegrind: included in both workload legs (all marker streams parse depths
  when =min_depth > 1= or depths are stored).

* Workload definition (fixed)

On **rg.terra**, release =rsx= binary, data =benchmarks/data/medium=:

1. =rsx signif -t markers.tsv -p popmap.tsv -o … -d 5 -G M,F --test fisher=
2. =rsx depth -t markers.tsv -p popmap.tsv -o …=

Script: =scripts/perf/run_cachegrind_workload.sh=.

* Tensor-path follow-up (streaming Gram / bitset / Arrow tiles)

** 1. Row-stream + bitset polish

=bitset::count_masked= unrolls 1–4 word panels. Cachegrind on
=signif --test chisq= (medium): Ir drop ~0.57% vs pre-unroll
(=cachegrind-tensor-delta.txt= on implementer scratch).

** 2. PCA as streaming contraction

=compute_pca_with_source= documents and isolates
=accumulate_gram_streaming= (\(G \mathrel{+}= x x^\top\) upper triangle +
means, then centering). Production uses the dense double loop (best for
mid-density medium panels under Cachegrind).
=rank1_upper_update_sparse= is exact for sparse rows and is proven faster
on a 90%-zero synthetic microbench (=gram_tests=).

** 3. Arrow batches as tiles

=MarkerStream::freq_histogram_columnar= + =ArrowMarkerSource= override walks
typed depth columns without materialising =Marker=. Unit test
=arrow_columnar_freq_matches_marker_stream_and_is_faster= shows a clear
wall-clock win on 100k synthetic rows (see =arrow-columnar-bench.log=).
