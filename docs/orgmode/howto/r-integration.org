Two ways to use rsx from R: the *in-process* =rsxr= package (preferred), or
*subprocess* calls to the =rsx= CLI for existing RADSex-style pipelines.

* Preferred: =rsxr= (in-process C API)

Install from the monorepo subdirectory (needs =cargo=; see =rsx-r/README.md=):

#+begin_src r
pak::pak("HaoZeke/rsx-rs/rsx-r")
# or: remotes::install_github("HaoZeke/rsx-rs", subdir = "rsx-r")
library(rsxr)
rsx_version()
#+end_src

High-level workflow returns tibbles:

#+begin_src r
mt <- marker_table("markers.tsv")
triaged <- triage(mt, popmap = "popmap.tsv", min_depth = 10L)
sig     <- signif_markers(mt, popmap = "popmap.tsv", test = "fisher")
#+end_src

* RADSex output compatibility

rsx produces byte-identical TSV to C++ RADSex when groups are specified
explicitly (=-G M,F= / =group1= / =group2=). Existing R helpers that read RADSex
marker tables, distributions, or alignments keep working without changes.

* Subprocess CLI (legacy / orchestration)

Build the binary once (pixi or cargo), then call it from R:

#+begin_src r
system2("rsx", c(
  "distrib",
  "-t", "data/markers_table.tsv",
  "-p", "data/popmap.tsv",
  "-o", "data/distribution.tsv",
  "-d", "5", "-G", "M,F"
))
#+end_src

Example pixi task that ensures =rsx= is on =PATH=:

#+begin_src toml
build-rsx = """bash -c 'if ! command -v rsx >/dev/null 2>&1; then \
  cargo install --path /path/to/rsx-rs/rsx-cli; fi'"""
#+end_src

Prefer =rsxr= when you want tibbles and no intermediate process; prefer the CLI
when a scheduler or Snakemake rule already shells out to =rsx=.
